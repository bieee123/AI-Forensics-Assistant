RUNBOOK: Credential Dumping Detection and Response

Indicators:
- Access to LSASS process memory (mimikatz, procdump, comsvcs.dll dump)
- Reading /etc/shadow, /etc/passwd, or SAM registry hive files
- Unusual access to Active Directory database file (ntds.dit)
- Volume shadow copy access for SAM/SYSTEM hive extraction
- Tools detected: mimikatz, lazagne, secretsdump, crackmapexec, john, hashcat
- Registry key access: HKLM\SAM, HKLM\SECURITY, HKLM\SYSTEM
- Process creation of known credential dumping tools
- Failed attempts with extracted credentials against other systems

Immediate Actions:
1. Identify the process and user account performing the credential dumping
2. Determine if credentials have already been extracted — check for files written to disk or network transfers
3. Identify which credential stores were accessed: LSASS, SAM, NTDS, shadow copies, browser stores
4. Check the range of credentials compromised — local accounts, domain accounts, service accounts, cached credentials
5. Force reset all potentially compromised credentials — start with privileged and service accounts
6. Examine network logs for authentication attempts using the potentially compromised accounts
7. Review recent authentication events across the environment for anomalous logins

Severity Classification:
- High: Local credential dump (SAM, cached credentials), limited scope, no domain compromise
- Critical: Domain credential dump (NTDS, LSASS on domain controller) or successful lateral movement with extracted credentials

Credential Rotation Strategy:
- Tier 1 (immediate): Domain admin, enterprise admin, built-in administrator accounts
- Tier 2 (within 4 hours): Service accounts, privileged application accounts
- Tier 3 (within 24 hours): All domain user accounts that were cached on the compromised system
- Tier 4 (within 72 hours): All remaining accounts with access to sensitive resources

Common Credential Dump Techniques:
- Mimikatz sekurlsa::logonpasswords (LSASS memory)
- Procdump + mimikatz offline analysis
- Volume Shadow Copy SAM hive extraction
- NTDS.dit export using ntdsutil or vssadmin
- Browser credential extraction from Chrome/Firefox/Edge profiles
- DPAPI master key extraction for decrypting stored credentials

Prevention and Hardening:
- Enable LSA protection (RunAsPPL) to prevent LSASS access
- Implement Credential Guard on supported Windows systems
- Remove debug privilege from non-administrative accounts
- Limit who can access domain controllers interactively
- Use Protected Users security group for sensitive accounts
- Deploy endpoint detection and response (EDR) tools with credential dumping detection
